# Forgon Engine shared contracts
Author: Nitish

Contract version: 1. Packages use ESM TypeScript source exports (`@forgon/project-schema`, `@forgon/editor-core`); bundlers/tsx consume source, `tsc --noEmit` checks it. This document is the integration boundary for concurrent workers. Implementation lives in those packages, not copied UI or host types.

## Documents and identity

`SceneDocument = { schemaVersion: 1; sceneId: string; name: string; entities: Entity[] }`.
`Entity = { id: string; name: string; parentId: string | null; enabled: boolean; transform: Transform; components: Component[]; prefab?: PrefabInstance }`.
`Transform = { position: [number,number,number]; rotationEuler: [number,number,number]; scale: [number,number,number] }` (local coordinates, degrees). All numbers finite; zero and negative scales allowed.
`Component = { id: string; type: string; enabled: boolean; properties: Record<string, JsonValue>; entityRefs: string[]; assetRefs: string[] }`. Put engine-specific fields in `properties`; explicit reference lists permit validation without guessing strings. Components have project-stable IDs. Component `type` is a semantic runtime name (e.g. camera/light/render/collision/script); opening a script component never executes code.
`PrefabInstance = { prefabId: string; instanceId: string; sourceEntityId: string }`. Instances are materialized editable entities; instance members share instanceId and map one-to-one to prefab source IDs. Prefab regeneration/override replay is a later gate, not implied by this metadata.
`PrefabDocument = { schemaVersion: 1; prefabId: string; name: string; rootId: string; entities: Entity[] }` with exactly one root, connected hierarchy.
`AssetRecord = { id: string; name: string; kind: 'model'|'texture'|'audio'|'material'|'script'|'other'; path: string; provenance?: { source: string; license: string; generator?: string; hash?: string } }`.
`AssetRegistry = { schemaVersion: 1; assets: AssetRecord[] }`.
`ProjectManifest = { schemaVersion: 1; projectId: string; name: string; startScene: string; scenes: {id:string;path:string}[]; prefabs: {id:string;path:string}[]; assetRegistry: string }` in `game.project.json`.

IDs are nonempty ASCII `[A-Za-z0-9_-]`, max 128 chars, immutable across save/reload; `createId(prefix)` uses platform UUID. Human-authored names are nonempty. Arrays retain author ordering. Unknown structural keys are rejected; component properties are finite JSON. Paths are project-relative POSIX paths, no empty/dot/dot-dot segments, absolute paths, drive letters, backslashes, or NUL. Host must additionally resolve containment and reject symlink escapes.

Exports: `sceneSchema`, `prefabSchema`, `assetRegistrySchema`, `projectManifestSchema`; `parseScene(input: unknown, context?: ValidationContext): SceneDocument`, `parsePrefab`, `parseAssetRegistry`, `parseProjectManifest`; `validateProject({manifest,scenes,prefabs,assets}): void`; `serializeScene(scene): string`; `createEntity(name, parentId?): Entity`; `createScene(name): SceneDocument`.
`ValidationContext = { assets?: readonly AssetRecord[]; prefabs?: readonly PrefabDocument[] }`. Scene parsing always checks finite JSON, duplicate entity/component IDs, missing parents/entity refs and hierarchy cycles. Supplied catalogs additionally enforce asset and prefab/source/instance references. Project validation requires complete matching catalogs and project-wide unique IDs. Without catalogs, scene parsing is structural/local validation only; never label it full project validation.

## Commands, undo and external changes

`SceneCommand` discriminates on `type`: `create {entity}`, `delete {entityId}` (subtree, rejected if surviving component references it), `rename {entityId,name}`, `reparent {entityId,parentId}`, `transform {entityId,transform}`, `component {entityId,component}` (upsert by component ID), `remove-component {entityId,componentId}`, `batch {commands}`. All transactions validate once before commit; failure changes nothing. Undo/redo restores exact validated snapshots; external accepted replacement clears history so undo cannot resurrect stale disk data.

`new EditorStore(scene: SceneDocument, revision: string | null, context?: ValidationContext)`; getters `scene`, `revision`, `dirty`, `canUndo`, `canRedo`, `conflict`; `execute(command): void`, `undo(): boolean`, `redo(): boolean`, `subscribe(listener: () => void): () => void`.
Pure command application is also exported as `applyCommand(scene: SceneDocument, command: SceneCommand, context?: ValidationContext): SceneDocument`; input is never mutated. Exported `SceneConflict` and `ReconcileResult` name the store conflict and reconcile return types.
`reconcile(input: unknown, revision: string): 'unchanged'|'reloaded'|'conflict'`. Invalid input throws while preserving last valid state/history. Clean valid external update reloads; dirty update retains ours and records `{base,ours,theirs,revision}`; repeated same revision+content is idempotent. No automatic merge. `resolveConflict('ours'|'theirs'): void`: ours rebases onto external revision and remains dirty; theirs replaces and clears history. Neither writes disk. `prepareSave(): SaveSnapshot` returns detached `{document,expectedRevision}` and throws while conflict unresolved. `acknowledgeSave(snapshot,revision): void` records only the actual saved snapshot; intervening local edits remain dirty; intervening external revision invalidates acknowledgement. `scene` and conflict snapshots are detached copies; mutate through commands.

Keep the original SaveSnapshot object for acknowledgement (host serialization may use a copy). A watcher event matching a prepared save can arrive before its acknowledgement: it advances the baseline/revision while preserving newer local edits and undo; the subsequent matching acknowledgement is accepted once. Other accepted external replacements clear history. Scene identity cannot change within a store; open a new store to switch scenes. Commands/undo/redo are blocked during an unresolved conflict. A new document with null revision remains dirty until its first acknowledged create-only save.

## Optimistic IO boundary (implemented by project-io worker)

Exports in project-schema: `Revision = string` (opaque hash of exact file bytes), `SceneRead = {document: SceneDocument; revision: Revision}`, `SaveSnapshot = {document: SceneDocument; expectedRevision: Revision|null}`, `SaveSceneRequest = SaveSnapshot & {path:string}`, `SaveSceneResult = {status:'saved';revision:Revision}|{status:'conflict';current:SceneRead|null}`; `SceneIO = { readScene(path:string): Promise<SceneRead>; saveScene(request:SaveSceneRequest): Promise<SaveSceneResult>; watchScene(path:string,listener:(event:SceneWatchEvent)=>void):()=>void }`.
`SceneWatchEvent = {type:'changed';value:SceneRead}|{type:'invalid';diagnostics:Diagnostic[]}|{type:'deleted'}`; `Diagnostic = {path:string;message:string}`. Invalid/deleted events do not replace last valid scene. `null` expected revision means create-only, never unconditional overwrite. Host serializes compare+write across all app writers, uses atomic temp+rename, checks byte revision immediately before commit, reports external races/conflicts, confines paths and never runs project scripts. Atomic rename alone is not cross-process compare-and-swap: document and test OS constraints before claiming arbitrary third-party writer safety. Watch callbacks are notifications, not authority to overwrite dirty UI state.

## Agent boundary (implemented by agent bridge/service worker)

Shared exports: `ProviderId = 'codex'|'opencode'|'claude-code'`; `PermissionMode = 'inspect'|'supervised'|'auto-edits'|'full-local'`; `AgentContext = {files:string[];sceneId?:string;entityIds:string[];assetIds:string[]}`; `AgentRunRequest = {threadId:string;provider:ProviderId;model?:string;prompt:string;projectRoot:string;permissionMode:PermissionMode;context:AgentContext}`.
`AgentEvent` envelope `{runId:string;threadId:string;sequence:number;timestamp:string}` plus discriminated payload: `started {provider}`, `text {text}`, `tool {name,state:'started'|'completed'|'failed',text?}`, `diagnostic {diagnostic}`, `approval {requestId,description}`, `diff {paths:string[]}`, `completed {outcome:'succeeded'|'failed'|'cancelled',message?}`. Sequence monotonically increases per run; timestamp ISO UTC. No secrets in events. Provider capabilities/auth/protocols remain adapter-owned. Permission labels alone confer no sandbox guarantee.
`AgentService = {start(request:AgentRunRequest):Promise<{runId:string}>;cancel(runId:string):Promise<void>;approve(runId:string,requestId:string,allow:boolean):Promise<void>;subscribe(listener:(event:AgentEvent)=>void):()=>void}`. Host must enforce permissions; unsupported controls must be reported unavailable rather than simulated. Use this common interface or an explicit adapter at its boundary.

## Integration order

Consume shared exports directly. UI: commands -> store -> prepareSave -> IO -> acknowledgeSave; watcher -> reconcile, never blind replacement. Runtime: render by entity.id, retain selection for surviving IDs, play from detached snapshot. Host: parse unknown files at boundary, enforce project validation with catalogs, return byte revisions. Agents: write ordinary files through scoped host controls and stream provider-neutral events; events never silently approve writes. No renderer, filesystem, React, Tauri or provider dependency in schema/core.
