## Callable contract (Node host / IPC)

Import runtime functions from `@forgon/project-io/node`; `@forgon/project-io` exposes only browser-safe types (no Node runtime imports).

- `openProject(root: string): Promise<NodeProjectSession>`: canonical root, recovery, strict complete catalog validation; no project script import/evaluation.
- `planCreate(root: string, template = 'empty-3d'): Promise<CreatePlan>`: exact generated file list, canonical parent and blockedReason if destination exists.
- `createProject(root: string, template = 'empty-3d'): Promise<NodeProjectSession>`: destination must not exist; exclusively create root/files, validate exact fixture bytes; cleanup only files this invocation created.
- `createNodeProjectHost(pickFolder: () => Promise<string|null>): NodeProjectHost`: structurally matches UI `ProjectHost` without importing UI. `open`/`create` return its opened/failed union; `planCreate` is the same safe planning primitive. The native shell supplies the picker. Recent successful roots are memory-only for this host lifetime, revalidated when listed; persistent recent storage remains a shell concern. `openExample` is optional and not implemented by this adapter; use explicit `createProject(destination, 'hotel')` to create an independent fixture copy.
- `readProject(root: string): Promise<ReadProject>` and `ProjectReader.create(root)`, `.json(relativePath)`, `.asset(relativePath)`, `.containedPath(relativePath)` replace CLI reader behavior.
- Session `root`, `manifest`, `assets`, `prefabs`, `sceneIO`, `close():void`; `readCatalog():Promise<ReadProject>` refreshes full catalog.
- `sceneIO.readScene(path):Promise<SceneRead>`, `saveScene(SaveSceneRequest):Promise<SaveSceneResult>`, `watchScene(path, listener):unsubscribe`: shared schema signatures unchanged. Only registered scene paths allowed. Byte SHA-256 revisions; null expected revision is create-only.
- `readAuthoring():Promise<{document:AuthoringArtifact,revision:string}|null>`; fixed path `authoring/generated.json`.
- `saveAuthoring({path,scene,authoring,expectedRevision,expectedAuthoringRevision}):Promise<{status:'saved',revision,authoringRevision}|{status:'conflict'}>`: concrete bundle from SDK capture/bake/detach; requires current scene equals current artifact replay and proposed scene equals proposed replay. No unresolved conflicts or silently discarded manual changes.
- `readAsset(assetId):Promise<{asset:AssetRecord,bytes:Uint8Array,revision:string}>`: registered ID only, bounded 32 MiB bytes, metadata/provenance returned intact. IPC encodes bytes explicitly; never grant absolute read capability.
- Exceptions carry `code: ProjectIOErrorCode` and message. Codes: INVALID_PATH, INVALID_DOCUMENT, LIMIT_EXCEEDED, NOT_FOUND, IO_ERROR, ALREADY_EXISTS, CLOSED, UNRECORDED_CHANGES, AUTHORING_CONFLICT, RECOVERY_CONFLICT. IPC must preserve codes rather than turn rejection into success. Stale scene saves use shared conflict result; stale pair saves return status conflict.

## Completed implementation and proof (17 October 2026)

Resumed the existing reader/session/create/journal implementation rather than replacing it. Added the structurally compatible Node host adapter and real temporary-filesystem regression suite. Fixed the pair-save result inference error found by the initial type-check. Moved the final revision comparison into atomic replacement, after temp-file write/fsync and immediately before rename; applied it to single scene saves, both pair replacements and rollback. Journal creation itself is now atomic/create-only rather than an in-place write that can leave a truncated active journal. Temp cleanup only runs when this invocation actually created the temp file. Recovery validates scene identity and before/after authoring replay before changing either source. Unknown scene paths are refused even for a stale revision against a missing file. Public template/authoring parsing failures carry the documented error codes.

Verified on Windows, Node v24.2.0, pnpm 12.5.1:

- `pnpm --filter @forgon/project-io test`: **13 passed, 0 failed, 0 skipped**.
- `pnpm --filter @forgon/project-io typecheck`: **passed** (includes source and tests).

The tests exercise real project creation/open/reopen and byte revisions; existing destination refusal; creation failure cleanup preserving externally edited files and unrelated additions; default browser-safe and `/node` public entry points; registered asset bytes/provenance and the 32 MiB payload bound; script assets read only as bytes; malformed UTF-8, depth-65 JSON and the 2 MiB JSON bound; unsafe Windows/path forms; real directory junction escapes and file symlink escapes (both passed, no privilege skips on this machine); two sessions racing stale revisions; create-only and missing/deleted scene saves; invalid/dependency-missing/deleted watcher events; watcher/session disposal; persisted generated overrides and explicit pair-save stale revisions; reopen after all four before/after journal combinations; refusal to recover over unrelated external bytes or a deleted file. An actual child process also exits with a staged half-committed pair on disk; open restores both original byte sequences. That child stages the documented crash boundary; it does not interrupt `writePair` at an arbitrary instruction or simulate power failure.

Parsing/read bounds are 2 MiB per JSON file, 16 MiB catalog JSON total, 128 documents, 1024 registered assets, JSON nesting 64, and 32 MiB per explicit asset read. Journal bytes are bounded to 12 MiB, with each decoded document limited to 2 MiB. Catalog validation checks IDs, references, canonical file aliasing, binding declarations, and asset regular-file existence. Open neither imports nor evaluates generator modules, script assets, package scripts or project hooks.

## Parent integration and transport requirements

1. Root installation/lockfile is parent-owned; no install or root configuration change was made here. CLI keeps its existing read-only implementation until its owner switches imports to `@forgon/project-io/node`. No CLI/core/desktop/UI files were edited here.
2. Instantiate one Node host/service for the app. Its in-process queue is keyed by canonical project root (case-folded on Windows), so distinct sessions and root aliases share write serialization. Do not instantiate independent writer processes and assume they share that queue.
3. Native/Tauri IPC must own folder authorization and session IDs. Keep actual sessions in Node; return serializable manifest/assets/prefabs plus an opaque session handle. Construct renderer `SceneIO` proxies for read/save/watch/unwatch/close; never attempt to serialize functions. Scope each requested relative path/asset ID to that session. Watch subscriptions need unique IDs and removal on explicit unsubscribe, project switch, renderer disconnect and service shutdown.
4. Preserve coded exceptions and shared save/conflict results; encode asset bytes explicitly (binary IPC or base64). Use registry asset IDs rather than exposing a generic absolute-file-read command. Project roots may cross trusted native selection IPC, but web content must not be granted unrestricted root choice. The injected `pickFolder` is a native capability, not a fake Node dialog.
5. New-project selection must yield a **nonexistent destination with an existing parent**. This API intentionally refuses existing folders, including empty folders. The current UI's generic picker must supply a new child path/save-folder interaction for New; choosing an existing directory cannot complete this creation flow. Adding a project into an existing unrelated directory needs a separate safely reviewed create-only operation and is not implemented here. The fixture template IDs currently accepted by the underlying fixtures are `empty-3d` and `hotel`.
6. `NodeProjectSession` structurally supplies the UI session contract. UI still owns `prepareSave -> saveScene -> acknowledgeSave` and watcher reconciliation/conflict display; do not replace dirty state blindly. Session getters are detached snapshots; `readCatalog` refreshes them, but automatic UI registry/manifest navigation events are not part of `SceneIO`.
7. Generated visual saves automatically capture supported manual overrides and persist scene+artifact as a journaled pair. Structural authoring edits outside `captureOverrides` support fail explicitly with `AUTHORING_CONFLICT`. Bake/detach callers use `saveAuthoring` with both byte revisions and a scene equal to artifact replay. Existing unrecorded manual changes are refused, not discarded. Pair saves cannot change generator identity or prefab-binding declarations.
8. Pending journal recovery is rollback, not roll-forward: open/read/save restores exact originals only when both current files match recorded before/after bytes. Unrecognized or missing external versions produce `RECOVERY_CONFLICT`, preserve the journal and files, and require explicit recovery UX. No automatic deletion or guessing is authorized by that error.

## Precise safety and verification limits

Atomic sibling temp+rename provides complete-file replacement, not cross-process compare-and-swap. Noncooperating external writers can still change a destination after the final revision check and before rename, or change catalogs between validation and commit. Likewise, Node's portable path APIs cannot prevent a hostile process replacing directory ancestors between canonical checks and a filesystem syscall. Canonical confinement rejects existing symlink/junction escapes, but it is not an OS sandbox against adversarial concurrent namespace mutation. Native directory-handle-relative operations and/or an OS-enforced writer broker are required for stronger guarantees.

The pair journal supports recovery after process interruption; readers outside the host queue can see the intermediate scene/artifact pair. File contents and journal temp files are fsynced, but parent directories are not durably fsynced across platforms: power-loss durability is unverified. A process killed during temp-file writing can leave an unreferenced UUID `.tmp` sibling; live failure paths clean their own temps, and startup deliberately does not delete unknown files by filename pattern. This suite stages crash boundaries and verifies recovery, rather than claiming arbitrary-instruction kill or power-cut coverage.

Watcher delivery is debounced 50 ms with a 250 ms polling fallback and content/event deduplication. It validates the full catalog, so missing dependencies report invalid rather than scene deletion. No latency percentile, viewport update, native watch transport, browser, Tauri launch/build, packaging, or root-wide regression run was performed by this worker. Parent owns desktop integration and browser QA. No scripts were executed from an opened project, no dependencies installed, and no commits, branches, pushes or deployments were made.
